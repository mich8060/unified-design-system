# Consumer Tailwind v4 preset (opt-in)

Use this when a product app needs **its own Tailwind JIT** (arbitrary utilities, app-only layout classes) while still using UDS tokens and the published component stylesheet.

This addresses the “class silently no-ops” failure mode of **styles.css-only** apps (no local Tailwind scan).

## Two supported paths

| Path | When | What you import |
|------|------|-----------------|
| **Default** | Figma Make, thin apps, AI recipes | `styles.css` (or `styles/base.css`) only — no consumer Tailwind |
| **Opt-in** | Product apps that author app-level utilities | `styles.css` **plus** a consumer Tailwind build that imports `theme.css` and scans **app** source |

Keep the default path for simplicity. Use opt-in when you need classes that are not already in published `dist/styles.css`.

## Why `theme.css` (not a JS `tailwind.config`)

UDS is **Tailwind v4 CSS-first**. Token and `@theme` bridges live in CSS (`tokens.css`, semantic color/type themes, shadcn variable bridge). The published preset is:

```text
@chghealthcare/unified-design-system/theme.css
```

It includes:

- `--uds-*` design tokens
- Tailwind v4 `@theme` mappings (`bg-uds-surface-primary`, `text-uds-text-tertiary`, `bg-uds-color-accent-amber-*`, …)
- shadcn/UDS CSS variable bridge (`--background`, `--primary`, …)

It does **not**:

- `@import "tailwindcss"` / preflight
- Generate utilities for your app (your build does that)
- Replace `styles.css` for AppShell / Menu / component chrome

Align consumer `tailwindcss` / `@tailwindcss/vite` with the version UDS uses (currently **^4.2.x**).

## Recommended hybrid (avoids double preflight)

**1. JS entry — keep the prebuilt component stylesheet**

```tsx
import "@chghealthcare/unified-design-system/styles.css"
import "./index.css"
```

**2. App CSS — theme + utilities only, scan your sources**

```css
/* src/index.css */
@import "tailwindcss/theme" layer(theme);
@import "tailwindcss/utilities" layer(utilities);

/* Process UDS tokens/@theme in *this* Tailwind pipeline */
@import "@chghealthcare/unified-design-system/theme.css";

/* Authoritative scan set: your app (not node_modules) */
@source "./**/*.{ts,tsx}";

html,
body,
#root {
  width: 100%;
  min-height: 100dvh;
}
```

**3. Vite**

```ts
import tailwindcss from "@tailwindcss/vite"
import { defineConfig } from "vite"

export default defineConfig({
  plugins: [react(), tailwindcss()],
})
```

### Why not `@import "tailwindcss"` here?

Full `tailwindcss` includes **preflight**. Published `styles.css` already ships preflight (and UDS list restorations). Importing both causes **double reset** and hard-to-debug base styles. Prefer `theme` + `utilities` layers when `styles.css` is also loaded.

## What this fixes

- App classes such as arbitrary values (`top-[13px]`, `grid-cols-[200px_1fr]`) and variants that are **not** in the UDS safelist are generated by the consumer build.
- Utilities that reference UDS tokens (`bg-uds-surface-secondary`, `gap-[length:var(--uds-gap-24)]`, …) resolve because `theme.css` is part of the consumer Tailwind compile.

## What this does not replace

- **`Text` / component chrome** still need `styles.css` (or an equivalent full UDS stylesheet). See [`consumers-text-typography-tailwind-v4.md`](./consumers-text-typography-tailwind-v4.md).
- **AI recipe layouts** remain available styles.css-only via the recipe safelist — you do not need opt-in Tailwind for those class strings alone.
- Scanning `node_modules/@chghealthcare/unified-design-system` is **not** required for the hybrid path and is usually slower/noisier than importing `styles.css`.

## Checklist

1. Install `tailwindcss` and `@tailwindcss/vite` matching UDS’s major/minor.
2. Keep `import "…/styles.css"` once at the app root.
3. Add `theme.css` to the consumer CSS entry processed by Tailwind.
4. `@source` **app** files only (adjust the glob to your tree).
5. Do **not** also `@import "tailwindcss"` (full stack) while loading `styles.css`.
6. Smoke-test: an arbitrary utility in app JSX appears in DevTools; a UDS `Button` still looks correct.

## Amber accents

Public amber ramp: CSS vars `--uds-color-accent-amber-25` … `-1000`, and theme utilities `bg-uds-color-accent-amber-*` / `text-…` / `border-…` (shipped in `styles.css` and `theme.css`). Prefer system warning tokens for semantic warnings — see [`design-language/foundations/color.md`](../design-language/foundations/color.md).
